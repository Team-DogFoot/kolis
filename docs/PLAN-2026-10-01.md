   ```json
   "arrange": {
     "manuscripts_root": "원고",            // 정리 뒤 원고 상위 폴더(납품 폴더 기준 상대 경로). 회차 폴더만 들어간다

               {"from": "#섬네일", "to": "썸네일", "kind": "썸네일 폴더", "why": "…"}],
     "set_aside": [{"from": "원고 폴더 안의 Thumbs.db", "to": "_kolis_제외/…", "why": "이미지가 아님"}],
     "notes": ["사람이 알아야 할 점: 빈 폴더, 엑셀에 없는 폴더, 폴더에 없는 엑셀 행, 중복 의심 등"]

   ```
   기준을 스킬에 글로 적는다: 회차 폴더와 엑셀 행을 뜻으로 짝짓는다(본편과 외전 구분) / 폴더 이름은 `<세 자리 순번>_<권차 표기>` 처럼 엑셀 행 순서가 드러나게(어차피 2단계에서 콘텐츠ID 로 바뀐다) / 원고 폴더 안의 이미지가 아닌 파일은 지우지 않고 `set_aside` 로 뺀다 / 짝이 안 맞는 것은 옮기지 않고 `notes` 와 `issues` 에 적는다 / **파일을 지우는 계획은 쓰지 않는다**.
   `rows[].folder` 와 `thumb_source` 는 **정리 뒤의 이름**으로 적게 한다. 기존 `manuscripts_root`, `thumbs_dir` 최상위 키는 `arrange` 의 값과 같게 유지한다(다른 코드가 읽는다).

5. **시험(프로그램 창, HANDOFF 0절 5번 방법)**: 새 작품을 원본 그대로 **복사해 둔 뒤**(원본 보존: `Downloads\484_…_원본사본`) 1번 실행 → 폴더가 `원고\…`, `썸네일\…` 로 정리됐는지, 반입용 엑셀 11행, thum_files 11개, 되돌리기가 원래대로 되는지. 그다음 되돌리고 한 번 더 실행해 두 번의 반입용 엑셀 값이 같은지 본다(09-29 확정). 기존 3작품(타임머신 대소동 등)이 깨지지 않았는지 타임머신 대소동으로 1번을 한 번 돌린다.

- **조회 요청은 실제로 보내 본다**: 가원부 1598(접수 924, 10건)·1599(접수 923, 20건)·1600(접수 925, 8건) 자료를 검색해 요청·응답 전문을 기록한다(`ie_dom.py` 기록 또는 프로그램 세션). 응답의 칸 이름과 뜻을 표로.
- 화면 방식에 필요한 것: 요소를 잡는 방법(크롬 엔진이면 CSS 선택자, IE 모드면 UIA 이름), 그리드 종류(jqxGrid 여부·가상 스크롤), 파일 대화상자 제목, 팝업 창 제목·클래스
- 직원에게 물어야 풀리는 것(목록으로): HANDOFF 4절 4번의 "디지털콘텐츠관리에서 어떤 번호로 검색합니까" 등

### 5-4. 방법
- **유저 지시는 "직접 브라우저를 열어서"다.** Edge 에서 KOLIS 에 로그인해(유저가 로그인해 주거나, 계정이 `.env` 에 있으면 그것으로. 비밀번호 5회 주의) 메뉴 경로로 화면을 연다. **주소를 직접 치면 로그인이 풀린다 — 메뉴로만 간다.**
- 크롬 엔진 화면은 Playwright `connect_over_cdp` 로 붙어 DOM·요청을 읽을 수 있는지 먼저 본다(Edge 를 `--remote-debugging-port` 로 띄워야 한다. Somansa DLP 때문에 Playwright 의 Node 쪽 요청은 실패한다 — 페이지 안에서만 읽는다. 메모리 `somansa-dlp-tls-interception`). IE 모드 화면은 `ie_dom.py`(HANDOFF 3절)로 DOM 과 요청을 기록한다. 먼저 `ie_dom.py` 를 읽고 쓰는 법을 확인한다.
- 화면 소스는 프로그램의 로그인 세션(`kolis_http`)으로 받는 것이 더 빠르고 온전하면 그 방법을 같이 쓴다. 다만 메뉴를 거치지 않은 GET 이 세션을 끊는지 모르므로, 처음 한 번은 영향이 없는 화면으로 확인하고 결과를 적는다.
- **누르지 않는 버튼**: 저장, 일괄변경 실행, 복본조사 실행(결과를 KOLIS 에 쓰는지 소스로 먼저 확인), MODS정리, 삭제, 전거·주제명 연결 확정. 팝업을 여는 것, 찾기·검색·조회는 누른다. 버튼이 쓰기인지 조회인지 모르겠으면 소스를 먼저 읽고, 그래도 모르면 누르지 않고 유저에게 묻는다.
- 가원부 1598·1599·1600 은 실제 자료다. 값을 바꾸지 않는다.

### 5-5. 산출물
- `docs/BUILD-CHECK-RECON.md`(새 문서): 화면별 5-3 표, 구축·점검 전체 순서도(글로), 단계마다 "요청 방식 초안(주소·항목·본문 예시)"과 "화면 방식 초안(누르는 순서·요소 잡는 법·확인창 문구)", 단계마다 **실행 전 확인·실행 후 확인**에 쓸 조회 요청, 모르는 것 목록, 직원에게 물을 것 목록. 계정·쿠키·제품 키는 적지 않는다.
- 코드 뼈대: `kolis_request.py` 에 조회 요청(검색·목록·MODS XML)을 함수로 추가하고, 저장된 응답으로 대조하는 검사(`check_saved` 방식)를 붙인다. 쓰기 요청은 함수로 만들어 두되 **프로그램 창의 버튼에 연결하지 않는다**(원부번호 작품이 생겨 유저가 실행하자고 할 때 연결). 넘어가기 구조는 기존 원칙: 요청이 나가기 전의 실패만 화면 방식으로, 나간 뒤의 실패는 멈춤.
- 그 1회 실행의 **순서표**(RECON 문서 끝): 단계별로 무엇을 보내고, 무엇을 확인하고, 실패하면 어디서 화면 방식으로 넘어가는지, 그날 기록(`ie_dom.py`·journal)을 어떻게 켜 두는지. 한 번뿐이므로 기록은 전부 켠다.

## 6. 작업 순서 (권장)
1. 2절의 남은 일 1~5(스킬·검사·문서 정리). KOLIS 와 무관, 재료 소모 없음.
2. 3절: 1단계 AI 정리 기능 → 새 작품으로 1번 시험(원본 사본을 먼저 만들어 둔다) → 유저·직원과 반입용 엑셀 확인.
3. 4-2 의 1·2번(소스 읽기)으로 썸네일 요청 형식 → 4-3 구현 → 4-5 시험(가원부번호까지, 두 번).
4. 5절 사전 수집. 3번에서 KOLIS 세션·기록 도구를 이미 다뤘으므로 그 뒤에 한다. 유저가 순서를 바꾸라고 하면 따른다.
5. 세션 끝 절차(HANDOFF 0절 9번): EXECUTION-LOG, FIELD-CHECKLIST, HANDOFF, README, `docs/memory/` 갱신 → 커밋·푸시.

## 7. 일하는 태도(유저가 이 모델에게 바라는 것)
- 유저는 합리적이고 사람다운 판단을 원한다. 규칙을 글자 그대로만 따르다 목적을 놓치지 않는다: 목적은 **직원이 쓰는 프로그램이 실제로 도는 것**이다.
- 막히면 "불가"라고 하기 전에 원인을 확인하고 다른 방법을 찾는다(09-29 에 근거 없이 "불가"라고 했다가 틀린 적이 있다 — REQUEST-AUTOMATION 2절).
- 확인하지 못한 것은 확인했다고 쓰지 않는다. 명령줄로 본 것은 시험이 아니다. 보고는 빠짐없이, 용어는 풀어서, 비유 없이.
- 질문에는 답만 한다. 이 문서의 일은 유저가 지시한 것이므로 진행하되, 이 문서에 없는 새 기능을 덧붙이지 않는다. 범위를 줄이지도 않는다.
- 유저에게 물어야 하는 것은 모아서 한 번에, 묻는 동안 다른 일을 계속한다.
