**유저 지시(2026-10-03 저녁):** 반입용 메타데이터 에이전트의 성능을 올릴 때 기준은 셋뿐 — `docs/source/2_지침`(MODS 입력가이드·정리지침서·매뉴얼), `docs/source/1_프로세스` 가이드, 예시 파일 **하나** `완료사례_코리스반입용_로맨스낫로맨틱(88열).xlsx`. **채점 틀(정답지 대조·점수)을 만들지 않는다.** 작업자 완료 폴더(Desktop 의 1.구축)는 정답이 아니다. 전거 번호·주제명 번호·둘째 출처정보 열을 반입용 엑셀에 끼워 넣는 길은 가지 않는다. 썸네일 파일명은 지금 관행.

**Why:** 내가 "채점 틀부터"를 추천했다가 "채점 만들지 말고 가이드나 지침이나 예시대로만 만들어라"로 바로잡혔다. 기준 자료가 아닌 것(개인 작업 폴더)을 정답으로 삼는 것은 출처 확인 규칙([[say-unverified-and-blockers-first]]) 위반이기도 했다.

**단서(10-03 밤):** 그 뒤 유저가 "다 테스트 해봐"로 반입 헤더 시험을 허용했고, 전거·주제명·UCI·다른이름·출처정보 2묶음이 전부 반입됨이 확인됐다. '끼워 넣지 않는다'는 유저가 다시 정할 때까지 유지하되, 근거는 `BUILD-CHECK-RECON.md` 9절.

**How to apply:** 스킬에는 가이드 조항을 번호와 원문으로 심는다(요약 금지). 양식 쓰기는 예시 파일처럼 MODS 경로 열을 필요한 만큼 반복(저자·발행처·주기), 주제명은 `만화` 만(웹툰은 구축에서 장르주제명). 시험은 예시 파일 역변환 → 셀 단위 동일 확인 + 시험 폴더 1건 실행 → 조항별 대조 보고. 저장은 유저가 시작(1614 2화부터). 관련: [[kolis-webtoon-project]], [[agent-first-fixed-output]].
