KOLIS 단계는 **브라우저를 띄우지 않고** 프로그램이 `.env` 의 계정으로 직접 로그인해 요청만으로 한다. 실패에 대비한 "이어서 실행" 같은 장치를 만들지 않는다. 다시 실행하면 되고, 남는 접수번호는 `work/취소요청_목록.csv` 에 적어 주무관에게 취소를 요청하면 된다.

**Why:** 2026-09-30 유저 지시. 그 전에 나는 "로그인된 Edge 화면 안에서 요청을 보내는 방식"을 골라 Edge 를 띄워 둬야 하는 조건을 붙였고, 파일을 보내는 단계를 근거 없이 "불가"로 적었고, 반입 두 번 방지·이어서 하기 같은 장치를 덧붙였다. 유저는 셋 다 불필요하다고 했고, 실제로 브라우저 없이 28.9초에 전 과정이 됐다.

KOLIS 가 주는 파일(전체출력 등)은 **받은 파일을 그대로** 넘긴다. 값을 읽어 새 파일로 다시 만들지 않는다(2026-09-30 직원 검수에서 내가 만든 가원부 xlsx 가 형식 불일치로 지적됨).

**How to apply:** 새 KOLIS 단계(썸네일, 구축, 점검)도 먼저 요청으로 만들 수 있는지 본다. 요청 형식은 화면의 스크립트와 브라우저가 PC 에 남긴 파일(INetCache)에서 읽을 수 있다. 화면 조작(pywinauto)은 마지막 수단. 계정은 `.env` 에서만 읽고 어디에도 적지 않는다(유저가 대화에 적어 줘도 옮기지 않는다). 비밀번호 5회 실패 시 계정이 잠기므로 로그인은 실행당 한 번만. 관련: [[kolis-automation-strategy]] [[say-unverified-and-blockers-first]]
