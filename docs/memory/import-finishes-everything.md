**유저 확정(2026-10-04, 맥북에서):**
1. 목적은 "무조건 가능한, 최대한 최초 반입용 메타데이터 작성에서 모든 걸 끝내는 것". 10-03 밤 반입 헤더 시험(전거·다른이름·디스플레이형식·주제명 2묶음·UCI·출처정보 2묶음·발행처 2칸·판사항·수상 주기 전부 반입됨)은 이를 위한 실험이었다. → 10-03 저녁의 "전거·주제명·둘째 출처정보를 엑셀에 끼워 넣지 않는다"는 **폐기**. [[import-quality-by-guide-only]] 의 그 부분은 더 이상 유효하지 않다(기준이 지침·가이드·예시 하나라는 부분과 채점 틀 금지는 유지).
2. **MODS 헤더를 고정하지 않는다.** 반복 가능한 묶음(표제정보·저자·다른이름·출처정보·발행처·주기·주제명·식별기호·원문주소·분류·연관정보)은 **n묶음, 상한 없음**(유저 보충: "2묶음으로 고정하는 것도 아니다, 그 이상 있으면 더 여러 묶음"). 묶음 수는 작품 행들의 최대치. 83열 템플릿 같은 고정 열 목록을 두지 않는다. 주제명 '만화·웹툰 둘만'은 직원 답변의 내용 규칙이지 구조 상한이 아니다. 양식 쓰기는 "MODS 트리 → 열 직렬화 규칙"으로.
3. **하위호환성을 신경 쓰지 않는다.** 서버·백엔드·에이전트·헤드리스·UI·기존 코드 전부, 필요하면 갈아엎는다.

**Why:** 반입에서 끝내면 ③구간(구축 5.3)의 회차별 저장 작업이 대조·보정으로 줄고, 사람 확인 지점이 반입 전 한 곳으로 모인다.
