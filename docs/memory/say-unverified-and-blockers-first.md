작업 중에 안 될 것 같은 부분, 빠진 기록, 확인하지 못한 단계를 발견하면 **그 자리에서 먼저 말한다.** 보고서 표의 한 줄로 넘기지 않는다. "불가"라고 적기 전에 원인을 확인하고 다른 방법을 찾아본다. 말을 할 때 범위를 좁게 말해 놓고 넓게 들리게 하지 않는다.

**Why:** 2026-09-29 에 일괄반입·원문일괄등록을 근거 확인 없이 요청 방식 "불가"로 적었고(실제로는 기록 도구 결함 + 업로더가 설치형 부품), "작품을 더 안 써도 된다"고 했다가 뒤집었고, 실행해 본 적 없는 단계(썸네일 등)까지 한 버튼에 합치면서 그 사실을 말하지 않아 유저가 크게 화를 냈다.

**How to apply:** "확인됨"은 프로그램 창에서 실제 작품으로 KOLIS 에 실행해 결과가 맞은 것만 가리킨다([[test-through-the-program]]). 코드 작성, 손 조작, 저장된 기록 대조는 따로 구분해 말한다. 단계를 묶거나 자동으로 잇기 전에 각 단계가 어느 상태인지 표로 먼저 알린다. 유저가 "상식적으로 말이 안 된다"고 하면 판정을 방어하지 말고 근거부터 다시 확인한다. 관련: [[never-reduce-scope-on-my-own]]
