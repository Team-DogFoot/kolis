**전략(유저 확정 2026-09-18):** ① pywinauto UI 자동화 + 사람 확인 지점으로 ①~⑤ 전 과정 반자동 완성 → ② 실제 업무 때 IEChooser(`%SystemRoot%\System32\F12\IEChooser.exe`) 로 HAR 를 켜 두고 요청·응답 분석 → HTTP 클라이언트로 교체. 테스트 데이터가 없어 시험 요청 불가. Playwright 는 IE 모드를 못 다루므로 중간 단계로 쓰지 않는다.

**KOLIS/IE 모드 자동화에서 실측한 규칙(2026-09-18~19):**
- 주소 직접 입력 → 로그인 풀림. 메뉴 클릭(수집→납본→온라인 납본자료접수)만. 공지 레이어 `fixedNotice` 닫기.
- 요소는 UIA 이름으로 잡힘(`Internet Explorer_Server` 하위). confirm/alert = Win32 `#32770` '웹 페이지 메시지'(win32 백엔드). **같은 제목 창이 연속으로 뜨므로 "사라지거나 문구가 바뀜"으로 대기.** 알림창이 열려 있으면 뒤 클릭 전부 무시 → 단계마다 먼저 확인.
- **프로그램 창이 KOLIS 버튼을 덮으면 클릭이 프로그램 창에 떨어진다**(set_focus 로 안 풀림) → 실행 중 앱 창 최소화. 팝업 클릭 전 Edge 본창 → 팝업 순 포커스.
- 그리드 행 체크박스(jqxGrid)는 UIA 상태 없음 → **픽셀 판정(셀 중심 14px 중 어두운 비율 >3%) + 클릭 후 재확인**(토글이라 이미 체크된 걸 누르면 풀림). 헤더 전체선택은 UIA CheckBox.
- IE `select` 는 UIA `select()`·글자 입력이 값을 못 바꿈(성공처럼 보임) → 방향키로 옮기며 콤보 값 읽고, 확정 후 셀 텍스트 재확인. 원문유형 순서: 열람·표지·목차·초록·원본·썸네일. 열람으로 잘못 등록 시 유형 변경 불가 → 행 삭제 후 재등록.
- 파일 대화상자: 일괄반입 '업로드할 파일 선택', 썸네일 '열기'. 파일 이름 칸에 직접 값 쓰고 읽어 확인 → 열기 → 닫힘 확인, 실패 시 취소.
- 반입용 엑셀 thum_files 는 수정 팝업에 0 Bytes 자리표시자 행을 만든다 → 삭제·저장 후 진짜 파일 등록(유저 정의 절차).
- 원문일괄등록(폴더): 드래그&드롭은 사람이, 그 뒤 전송하기·일괄정보입력·원문등록은 UIA 클릭 가능. DEXT5 진행창은 UIA/win32 로 안 읽힘(캡처만). 원고 폴더 안에 이미지 외 파일이 있으면 33% 에서 멈춤 → 기록 파일은 `_kolis_manifests/` 로.
- 전체출력 `.xls` = SpreadsheetML(정규식 파싱). 목록 표시 중 접수번호 변경 시 "그리드가 초기화 됩니다" 확인창. 결과표는 가상 스크롤(11행만 읽힘).
- 소요: 반입 수 분, 원문일괄등록 2.3GB 33분, 일괄정보입력 0.5초/건, 원문등록 2초/건, 썸네일 등록 20~30초/건.

**How to apply:** 새 KOLIS 단계는 먼저 UIA 로 요소 이름을 읽고 `kolis_ui._act`(누름→확인→재시도) 패턴으로 만들고, 실패 시 캡처(`work/logs/fail-*.png`). 유저 지적: **클릭 자동화는 반드시 클릭 후 상태를 검증**할 것. 관련: [[kolis-webtoon-project]]
