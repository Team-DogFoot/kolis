**무엇(유저 2026-10-03):** KOLIS 납본 대행은 앞으로 웹툰 외에도 자료 종류가 늘어난다(**최대 32종**이라고 함: 웹툰 / 전자책 / …). 프로그램 UI 최상단 계층은 **자료 종류**, 그 아래 **작품(탭)**, 그 아래 **단계 A "처음 ~ 가원부번호"**(1 납품 폴더 → 반입용 엑셀, 2 KOLIS 등록, 단계별 실행)와 **단계 B "원부번호 ~ 끝"**(5.1 복본조사·5.2 일괄변경, 5.3 MODS 구축(회차별), 5.4~5.8 점검·납품), 각 단계는 접었다 펼 수 있어야 한다(flat 하게 다 펼쳐진 화면은 헷갈린다). UI 는 10-03 에 이 계층으로 고쳤다(`kolis_tool/ui/index.html`: 자료 종류 선택, `<details class="phase">`).

**내부 로직은 지금 바꾸지 않는다(유저).** 대신 종류가 늘 때 갈라질 지점을 알고 개발한다:
- 자료 종류별로 달라지는 것: 반입용 엑셀 양식(열), 스킬·규칙(`agent_home/.claude/skills/*`, `docs/rulebook/*`), KOLIS 화면(등록구분 코드 FTX=웹툰, 메뉴 경로), 주제명·장르 고정값, 사업별 고정값(입수처 주기 등 `work/build_settings.json`).
- 공통인 것: Edge+Playwright 조작(`kolis_browser.py`), 요청 기록, 에이전트 실행기(`agent.py`), 검사 틀(`checks.py`), 상태 파일(`work/build/*/state.json`), 프로그램 창 틀(탭·로그·_run).
- 추상화 후보: `kinds.py`(종류 레지스트리: 이름, 등록구분 코드, 양식 파일, 스킬 이름, 메뉴 경로, 고정값) → 앱·스킬·검사·화면이 종류를 인자로 받게. 지금은 웹툰 하나만 들어 있는 상수로 둬도 된다.
- 단계 B 는 ③구간 요청 기록(`work/logs/browser-*.jsonl`)으로 자동(요청 방식)을 만들 때 종류와 무관한 공통 코드가 되게 한다.

**원문 관찰 기록(유저 10-03):** 다른이름은 회차마다 원문이 다를 수 있어 회차별로 적어야 한다. ①단계(prepare-import)가 회차마다 원문을 읽을 때 "표제면·판권기·표지의 저자 표기·다른 이름·발행처 표기" 관찰을 회차별 파일로 남겨 ③단계(build-mods)가 재사용한다. ①을 거치지 않은 작품(남이 등록, 예 원부 1607)은 ③단계에서 원문 폴더를 받아 회차별로 읽는다(3번 카드 "원문 폴더" 칸). ③단계는 원부번호(+원문 폴더)만으로 시작할 수 있다.

**Why:** 다음 세션(모델이 바뀌어도)이 종류 추가 요구를 받았을 때 어디를 가르면 되는지 알게. **How to apply:** 새 코드를 쓸 때 웹툰 고정값(FTX, 만화/웹툰 주제명, 810 등)을 함수 깊숙이 박지 말고 상수·설정으로 빼 둔다. 관련: [[kolis-webtoon-project]] [[agent-first-fixed-output]]
