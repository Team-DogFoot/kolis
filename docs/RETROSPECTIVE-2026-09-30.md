## 2. 진행 순서
1. 개발용 3작품으로 기존 코드 실행 → 출판사 엑셀 양식이 달라 실패 → 읽기·조사·판단을 에이전트로 옮김(스킬, 자기 검사, 검수 에이전트, 쌓이는 지식).
2. 화면을 "폴더 + 지시·메모 + 실행" 하나로, 작품 탭, 표준 엑셀과 `_source` 시트 제거.
3. 직원이 타임머신 대소동의 반입용 엑셀을 검수(고친 값 5종 → `knowledge/corrections.md`).
4. 타임머신 대소동으로 화면 방식 전 과정(접수 939, 가원부 2026-1615). 이때 화면 안 기록 도구(`ie_dom.py`)로 요청을 기록.
5. 기록으로 요청 방식 분석 → 처음엔 "Edge 화면 안에서 요청 보내기"로 만듦 → 유저 지시로 **브라우저 없이 직접 로그인**으로 바꿈 → 전 과정 성공(접수 941).
6. 프로그램 창에 KOLIS 계정 로그인 칸 추가(접수 942 로 확인).
7. 직원 기능 검수: 가원부 파일 형식 불일치 → KOLIS 에서 받은 파일 그대로 저장하도록 고침(접수 944).

## 3. 시행착오 (잘못한 것 → 원인 → 고친 것)
| 잘못한 것 | 원인 | 고친 것 / 교훈 |
|---|---|---|
| 명령줄로 돌려 보고 "시험했다"고 보고 | 빠른 길을 택함 | 시험은 프로그램 창으로만(CDP 로 실제 버튼을 누름) |
| 에이전트 결과가 실행마다 달라지는 것을 당연하게 보고, 그다음엔 코드의 결론 규칙으로 막음 | 에이전트를 함수처럼 한 번 부르고 끊음 | 에이전트가 스스로 검사·수정·검수하는 구조로. 결정론적 규칙으로 메우지 않는다 |
| 근거 없이 모델을 바꾸고 금액을 보고 | — | Sonnet, 금액은 보고하지 않음 |
| **일괄반입·원문일괄등록을 요청 방식 "불가"로 판정** | 근거를 확인하지 않음. 업로더 전송이 기록에 없는 것을 보고도 말하지 않음. 기록 도구가 주소가 빈 프레임을 건너뛰는 결함 | 업로더 파일을 읽어 전송 형식 확인 → 요청으로 구현. "불가"라고 적기 전에 원인을 확인하고 다른 방법을 찾는다. 빠진 것은 그 자리에서 말한다 |
| 쉬운 단계(목록, 가원부번호)부터 요청으로 옮기고 핵심(반입, 원문 전송)을 남김 | 되는 것부터 함 | 화면을 붙잡는 단계가 하나라도 남으면 전체 이득이 없다. 핵심부터 |
| "Edge 에 로그인해 둬야 한다"는 조건을 말없이 붙임 | 로그인 요청을 몰라 로그인된 화면을 빌려 씀 | 브라우저 없이 계정으로 직접 로그인 |
| 확인 안 된 단계(썸네일 등)까지 한 버튼에 넣으면서 말하지 않음 | — | 단계를 묶기 전에 각 단계가 어느 상태인지 먼저 알린다 |
| "작품을 더 안 써도 된다"고 했다가 뒤집음 | 좁은 범위의 말을 넓게 들리게 함 | 실제로 되는지는 실제 작품으로 돌려야만 확인된다 |
| 이어서 실행, 반입 두 번 방지 같은 장치를 덧붙임 | 재료가 한 번뿐이라는 옛 전제 | 매번 처음부터. 남는 접수번호는 취소 요청 |
| **가원부 파일을 값만 가져다 새 xlsx 로 만듦** | 출처를 확인하지 않은 xlsx 3개를 "직원이 준 기준"으로 삼음. "같다"는 보고는 열과 값만 본 것 | KOLIS 가 주는 파일은 받은 그대로 넘긴다. 기준으로 삼는 파일의 출처를 먼저 확인한다 |
| 받으라는 지시에 받은 파일의 구조부터 분석 | 지시보다 내 방법을 앞세움 | 지시한 일을 먼저 한다 |
| Edge 를 최대화해 터미널을 가림 | 버튼이 창 밖에 있어서 | 최대화하지 않고 옆에 배치. (브라우저 없는 방식에서는 해당 없음) |
| 메모리 색인을 한 줄만 남기고 덮어씀 | PowerShell 명령 실수 | 파일 쓰기 도구로 복구 |
