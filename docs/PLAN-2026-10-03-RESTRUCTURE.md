## 1. 원부 일괄 처리 화면 (과장님용)

### 1-1. 위계
```
웹툰 ▾
 ├ 원부 일괄 처리            ← 새 화면(탭 줄 맨 왼쪽 고정 탭, 닫히지 않음, 이름 "원부 일괄 처리")
 ├ 작품 탭 … (지금과 같음)
 └ ＋ 작품 추가
```
- 자료 종류 바로 아래, 작품과 같은 층. 고정 탭 하나. 작품 탭의 3-1 은 **읽기 전용 상태**("복본조사 완료 · 일괄변경 완료 · 성인물 → 이용제한 완료")만 남긴다.

### 1-2. 입력
- 원부번호: 범위(`1607-1620`)와 나열(`1607, 1610, 1614`) 섞어서. 붙여 넣기 가능. 연도는 올해 고정(지금과 같음), 등록구분 FTX.
- 단추: 「화면 열어 확인」(원부마다 등록원부관리 조회만 → 건수·상태·작품명, 이미 끝난 원부 표시) / 「복본조사 실행」.

### 1-3. 흐름(한 번의 실행)
1. 원부마다 등록원부관리 조회(읽기) → 작품명·건수·상태. 이미 복본조사완료(DS_3300 이상)면 건너뜀으로 표시.
2. 일괄복본조사 화면에서 **연속 구간은 시작·끝으로 한 번에**, 나머지는 원부마다 실행. KEY 설정은 처음 한 번만 확인.
3. 결과 표를 원부별로 나눈다(결과 행의 ACCESSION_NO 앞자리·원부 열로 구분. 첫 실행 때 확인하고 안 되면 원부마다 따로 실행으로 고정).
4. 후보가 **없는** 원부: 완료 대상으로 표시(아직 완료 안 함).
5. 후보가 **있는** 원부: 지금의 에이전트 판정(`judge-duplicates`)을 원부마다 돌려 판정 표를 만든다(원부끼리 동시, 에이전트 한도 3).
6. 화면에 원부 한 줄씩 결과. 이 실행에서 KOLIS 를 바꾼 것은 복본조사 실행뿐(다시 돌릴 수 있음).

### 1-4. 결과 표(원부 한 줄)
| 열 | 내용 |
|---|---|
| 선택 | 체크(완료·일괄변경 대상 고르기) |
| 원부번호 · 작품명 | 등록원부관리에서 읽음 |
| 건수 | 종 수 |
| 복본조사 | 후보 없음 / 후보 n종 → 판정(복본 a·아님 b·판단 불가 c) / 이미 완료 / 실패 |
| 완료 처리 | ○ 전 / ✓ 시각 |
| 일괄변경 | ○ 전 / ✓ 시각 · CH1·CH11·PE |
| 비고 | 판정 요약 첫 문장, 펼치면 10-03 에 만든 판정 근거 표(우리 자료 기준, 5줄 페이지) |

- 아래 단추: 「고른 원부 완료 처리 + 일괄변경」(확인 체크 → 대화상자 → 원부마다 완료 → 재조회 → 일괄변경 → 재조회). 후보 없는 줄은 기본 선택, 후보 있는 줄은 기본 해제·노란 표시. 과장님이 판정 표를 보고 직접 선택해 완료할 수 있다(복본 짝은 체크한 채로 완료).
- 페이지: 20원부씩.

### 1-5. 백엔드
- `build_prep.dupexmin` 을 원부 하나 단위 함수로 그대로 두고, 위에 `ledger_batch.run(ranges)` 를 얹는다: 상태 조회 → 범위 묶기 → 실행 → 원부별 결과 분리 → 판정 → `work/build/wonbu_<n>/` 에 지금과 같은 파일(상태·결과 표·판정). 완료·일괄변경은 `dup_complete`·`batch_change` 를 원부마다 호출.
- 기록: 한 실행 = 하나의 `work/logs/ledger-batch-<시각>.jsonl`(원부 목록, 범위 묶음, 요청 수, 결과) + 브라우저 기록은 지금처럼.
- 작품 탭 3-1 은 `wonbu_<n>/state.json` 만 읽어 표시(코드 이미 있음, 단추만 뺀다).

### 1-6. 배분과 연결
- 완료·일괄변경이 끝난 원부는 「＋ 작품 추가」의 이전 작품 목록에 "원부번호 · 작품명 · 준비됨"으로 뜬다. 직원은 거기서 골라 탭을 연다(작업 폴더 없이 원부번호만으로 B 단계 시작 — 지금 되는 경로).

1. 원부 일괄 처리 탭 이름과 위치(탭 줄 맨 왼쪽 고정) — 이대로 갈지.
