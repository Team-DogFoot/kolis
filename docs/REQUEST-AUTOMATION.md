# 요청 방식 자동화 — 가능한 범위 (2026-09-29 분석)

용어
- **화면 방식**: 프로그램이 Edge 의 KOLIS 화면에서 버튼을 누르고 글자를 넣는 방식. 지금까지 만든 KOLIS 단계가 전부 이 방식이다.
- **요청 방식**: 화면을 누르지 않고, 화면이 버튼을 눌렀을 때 KOLIS 서버로 보내는 것과 같은 내용을 프로그램이 직접 보내는 방식.
- **요청 기록**: 화면이 서버와 주고받은 내용(주소, 보낸 값, 받은 값)을 남긴 파일. `work/captures/rec/<시각>/requests.jsonl`. 저장소와 PC 밖으로 내보내지 않는다.

근거: 타임머신 대소동(접수번호 939 → 가원부번호 2026-1615)을 화면 방식으로 끝까지 진행하면서 받은 요청 기록 223줄(요청 36건, 확인창·알림창 11건, 팝업 4건, 폼 전송 4건).

## 0. 결론 (2026-09-30 실행으로 확인)

**반입용 엑셀 확인 뒤의 KOLIS 등록은 브라우저 없이 전부 된다.** 프로그램이 `.env` 의 계정으로 직접 로그인해서 요청만으로 한다.

타임머신 대소동(3권, 이미지 192장, 26.7MB)을 프로그램 창의 "KOLIS 등록" 버튼으로 실행한 결과: 접수번호 941, 가원부번호 2026-1616, **전체 28.9초**, 확인 36개 통과, 요청 228건.

| 단계 | 시간 | 요청 |
|---|---|---|
| 로그인 | 1.1초 | `GET /main/login.do` → `POST /main/loginprocess.do` (uid, pwd, jsp_ip) |
| 일괄반입 | 0.9초 | `POST /online/reg/bo/accrectarget/fileUpload.do` (파일 첨부 형식) |
| 콘텐츠ID 받기 | 0.2초 | `POST …/onlineDepstRecet/selectMultipleOnlineDepstrecetList.do` |
| 원고 폴더명 | 0.4초 | (PC 안의 일) |
| 원문일괄등록 | 21.6초 | 파일마다 `POST /dext5upload/handler/dext5handler.jsp` → `setFileList.do` → 건마다 `getfileList.do`·`getTocFile.do`·`searchTextCheck.do`·`updateTextCheck.do` → 건마다 `insertContentsText.do` |
| 등록대상처리 → 가원부번호 → 가원부 파일 | 4초 | `updateTargetProcessing.do` → `insertTempAccessionRecNo.do` → `selectAccRecMngListWithParam.do` |

가원부 파일은 KOLIS 에서 받는다: 화면의 '전체출력'과 같은 요청(`POST /main/save.do`)을 보내 KOLIS 가 주는 `.xls` 를 그대로 저장한다. 값을 가져다 새 파일을 만들지 않는다(09-30 직원 검수: 새로 만든 xlsx 는 형식이 맞지 않음).

시험 방법(2026-09-30 직원 안내): 같은 작품으로 가원부번호까지 여러 번 실행해도 된다. 실행한 접수번호는 `work/취소요청_목록.csv` 에 남고, 마지막에 성공한 것만 두고 나머지는 주무관에게 취소를 요청한다.

코드: `kolis_http.py`(로그인·접속), `kolis_request.py`(요청 본문과 확인), `kolis_flow.py`(순서·확인·목록), `journal.py`(기록).

아직 브라우저 없이 하지 못하는 것: **썸네일 등록**(재료가 없어 요청을 본 적이 없음. 동봉된 납품이면 화면 방식 `kolis_thumbs` 를 부른다), **10MB 이상 파일**(업로더가 조각으로 나눠 보내는 방식은 만들지 않음. 있으면 시작 전에 멈춘다).

알아 둘 것
- 비밀번호를 5번 틀리면 계정이 잠긴다. 로그인은 실행당 한 번만 시도하고 실패하면 다시 시도하지 않는다.
- 업로더가 보내는 값은 `base64("R" + base64(값))` 로 감싼다(업로더 설정 encrypt_param=1). 응답도 같은 방식이다.
- 임시 저장 위치는 보내는 쪽이 정한다: `/Upload1/tmp/wonmun/<날짜+시각>/<콘텐츠ID>`. 파일 이름은 그대로 저장된다.
- 같은 계정으로 프로그램이 로그인해도 직원의 Edge 로그인이 풀리는지는 확인하지 않았다.

아래 1~4절은 이 결론에 이르기 전의 분석 기록이다(Edge 화면 안에서 요청을 보내는 방식, 화면 방식). 그 코드는 남아 있지만 프로그램의 기본 경로가 아니다.

## 1. 요청을 어떻게 보내는가

| 방법 | 가능 여부 | 이유 |
|---|---|---|
| 프로그램이 따로 접속(HTTP 클라이언트) | **지금은 불가** | 로그인 상태를 나타내는 쿠키를 화면의 스크립트에서 읽을 수 없다(화면에서 보이는 쿠키 7개 중에 세션 쿠키가 없음). 따로 로그인하려면 로그인 요청의 형식을 알아야 하는데 기록이 없다(로그인된 상태에서 시작했음). 계정을 프로그램이 다루게 되는 점도 있다 |
| **로그인된 KOLIS 화면 안에서 보냄** | **가능(채택)** | 직원이 로그인해 둔 Edge 의 KOLIS 화면에 스크립트를 넣어 그 화면이 요청을 보내게 한다. 로그인 상태를 그대로 쓰므로 계정·쿠키를 다루지 않는다. 마우스·키보드·창 위치와 무관하다 |

채택한 방법의 조건: Edge 에 KOLIS 화면이 로그인된 채로 하나 열려 있어야 한다(어느 메뉴든 상관없음). 알림창이나 팝업이 떠 있으면 그 뒤의 화면은 멈춰 있어 쓸 수 없다.

## 2. 단계별 판정 (2026-09-29 밤 고침)

처음 판정에서 일괄반입과 원문일괄등록을 "불가"로 적었으나 틀렸다. 근거를 확인하지 않고 내린 판정이었다(유저 지적). 고친 판정:

| 업무 단계 | 화면이 하는 일 | 자동 방식 | 코드 |
|---|---|---|---|
| **일괄반입** | `POST /online/reg/bo/accrectarget/fileUpload.do` (파일 첨부 형식, 항목 13개) → `{"receiptno": 접수번호}` | **요청으로 가능.** 파일은 프로그램이 읽어 본문을 만들고, 화면 안 스크립트가 그 바이트를 그대로 보낸다 | `kolis_request.import_excel` |
| 콘텐츠ID 받기(전체출력) | 화면이 목록을 XML 로 만들어 `/main/save.do` 로 되받음 | **요청으로 가능.** 목록 응답에 콘텐츠ID·원문 수·MODS 전문이 있다 | `kolis_request.export_receipt` |
| 폴더명을 콘텐츠ID 로 | (PC 안의 일) | — | `cnts_folders` |
| **원문일괄등록** — 폴더 올리기 | 업로더(DEXT5)는 IE 모드에서 **설치형 부품**으로 돈다(설정 `runtimes=ieplugin`, 폴더 전송은 이 방식 전용). 폴더를 끌어다 놓으면 업로더 스크립트가 부품의 `AddLocalFileDirectly(경로)` 를 부른다 | **스크립트로 가능(마우스 없음).** 팝업 화면 안에서 같은 함수를 직접 부른다 | `kolis_upload.add_folders` |
| 원문일괄등록 — 전송 | '전송하기' 버튼 = 업로더의 `Transfer` → 부품의 `StartFileTransfer`. 파일은 부품이 보낸다(그래서 화면 안 기록에 잡히지 않는다) | **스크립트로 가능.** `DEXT5UPLOAD.Transfer` 를 부른다. 전송 자체는 부품이 하므로 팝업은 열려 있어야 한다 | `kolis_upload.start_transfer` |
| 원문일괄등록 — 전송 뒤 | `setFileList.do` → 폴더마다 `getfileList.do`, `getTocFile.do`, `searchTextCheck.do`, `updateTextCheck.do`, `insertContentsText.do` | 팝업의 버튼(일괄정보입력, 원문등록)을 누름. 요청으로 옮길 수 있으나 아직 옮기지 않음 | `kolis_upload.run` |
| 원문 등록 확인 | 목록 요청의 CNT_FILES(원문 수) | 요청으로 가능 | `kolis_request.contents` |
| 썸네일 등록 | 기록 없음(재료 3작품에 썸네일이 없음) | 화면 방식(09-19 검증본) | `kolis_thumbs` |
| 등록대상처리 | `POST …/onlineDepstRecet/updateTargetProcessing.do` (JSON) | 요청으로 가능 | `kolis_request.target_process` |
| 가원부번호 발급 | 목록 요청 + `POST …/popup/insertTempAccessionRecNo.do` | 요청으로 가능 | `kolis_request.make_record` |
| 가원부 파일 | `POST …/onlineAccRecMng/selectAccRecMngListWithParam.do` | 요청으로 가능 | `kolis_request.export_record` |
| 복본 판정, 구축(전거·주제명), 점검 | 기록 없음 | 미정 | — |

업로더 분석의 근거: 브라우저가 내려받아 PC 에 남긴 업로더 파일(`%LOCALAPPDATA%\Microsoft\Windows\INetCache\IE\` 의 `dext5upload*.js`, `dext5upload.config.xml`)을 읽었다. KOLIS 에 요청하지 않았다. 설정 파일에는 제품 키가 들어 있으므로 저장소에 넣지 않는다.

남는 제약: 원문 전송은 팝업 안의 부품이 하므로 **원문일괄등록은 한 번에 한 작품**이다. 나머지 단계는 요청이라 여러 작품을 동시에 할 수 있다. 전송 시간(2.3GB 에 33분)은 회선 속도라 방식을 바꿔도 줄지 않는다.

## 3. 만든 것

- **프로그램 2번 "KOLIS 등록" — 버튼 하나**(`kolis_flow.py`): 일괄반입 → 콘텐츠ID 받기 → 폴더명 → 원문일괄등록 → (썸네일) → 등록대상처리·가원부번호·가원부 파일. 단계별 버튼은 "단계별로 따로 실행" 안에 접어 두었다.
- 방식: "요청 방식 우선"(기본) / "화면 방식". 요청 방식 우선일 때 **요청이 KOLIS 로 나가지 않은 경우에만** 같은 단계를 화면 방식으로 바꾼다. 요청이 나간 뒤의 실패는 KOLIS 에 반영됐을 수 있으므로 바꿔서 다시 하지 않고 멈춘다.
- 이어서 하기: 단계가 끝날 때마다 상태를 저장하고, 다시 실행하면 끝난 단계를 건너뛴다. **반입은 두 번 하지 않는다**(보내기 직전에 "보냈다"를 먼저 저장. 결과 미확인 상태로 멈췄으면 접수번호를 사람이 넣어야 이어 간다).
- 썸네일 분기: 납품에 썸네일이 동봉돼 있으면 등록, 없으면 하지 않는다.
- 확인(단계마다, 다르면 멈춤): 동의(YES), 엑셀 파일·시트(Sample, Contents)·행 수(1~500), 엑셀 행 수 = 원고 폴더 수, 원고 폴더에 이미지만 있음, 비고의 차수·번호, 반입된 건수·본표제 = 엑셀, 받은 목록의 접수번호·건수, 콘텐츠ID 중복 없음, 접수번호 뒷번호가 1부터 이어짐, 폴더 이름 = 콘텐츠ID, 원문이 아직 없음(전) / 전 건에 원문 있음(후), 전 건이 '접수' 상태, 등록구분 FTX, 이용대상·서비스범위가 섞이지 않음, 가원부 파일의 건수·콘텐츠ID = 반입한 것.
- 기록(`journal.py`): 실행마다 `work/logs/flow-<작품>-<시각>.jsonl`. 입력과 시작 상태, 확인한 조건과 값, 단계의 시작·끝·시간, 화면 로그 전부, 보낸 요청(본문)과 받은 응답(2만 자까지), 방식을 바꾼 이유, 멈춘 이유와 오류 위치.

## 4. 확인한 것과 확인하지 못한 것

"확인"의 뜻: 프로그램 창에서 버튼을 눌러 실제 작품으로 KOLIS 에 실행하고 결과가 맞게 나온 것.

| 항목 | 상태 |
|---|---|
| 요청 본문 6종(일괄반입 포함)이 기록과 같음 | 저장된 기록으로 대조(`kolis_request.check_saved()`). 일괄반입은 항목 이름·순서·값·파일 바이트가 같음 |
| 요청으로 만든 접수 목록 표·가원부 표가 실제 받은 파일과 같음 | 저장된 기록으로 대조 |
| 합친 실행의 건너뛰기·멈춤 | 끝난 작품(타임머신 대소동)으로 실행: 전 단계 건너뜀, 요청 0건. 동의 없이 실행: 첫 확인에서 멈춤 |
| 화면 안에서 요청을 보내고 응답을 받는 부분(`Page.send`) | **KOLIS 로 실행한 적 없음** |
| 화면 안에서 파일 바이트를 보내는 부분(IE 10 문서 모드) | **실행한 적 없음** |
| 일괄반입을 요청으로 보냈을 때 접수번호가 새로 생기는지 | **실행한 적 없음**(기록상 팝업 열기는 접수번호를 만들지 않고, 반입 응답에 접수번호가 온다) |
| 스크립트로 폴더 올리기·전송 시작 | **실행한 적 없음** |
| 등록대상처리·가원부번호를 요청으로 | **실행한 적 없음** |
| 썸네일 등록 | 09-19 에 다른 작품으로 11건. 그 뒤 공통 코드를 고친 뒤로는 실행한 적 없음. 재료가 없음(썸네일이 동봉된 작품 필요) |

첫 실제 실행: 직원과 반입용 엑셀을 확인한 작품 하나로, 프로그램 2번에서 "요청 방식 우선"으로 실행한다.
