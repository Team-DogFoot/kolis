## 2. 가장 쓸모 있었던 방법 — 화면의 스크립트를 화면 없는 Edge 에서 그대로 돌리기
KOLIS 화면은 버튼을 누르면 화면 안의 스크립트가 본문을 만들어 보낸다. 본문을 손으로 추측해 만들지 않고 **그 스크립트가 만드는 본문을 떠서** 그것과 똑같이 만드는 것이 가장 빠르고 안전했다.
1. 프로그램과 같은 방법으로 로그인(`kolis_http.Client`)해 쿠키를 얻는다.
2. Playwright 로 화면 없는 Edge(`channel="msedge", headless=True`)를 띄우고 쿠키를 넣는다. KOLIS 는 `http://` 라서 Somansa 가로채기와 무관하다.
3. 팝업은 부모 창의 표(`opener.grid`)를 읽으므로, 같은 출처의 빈 페이지에 `grid`·`$`·`bindDataToGrid` 대역을 만들고 거기서 `window.open` 으로 띄운다.
4. 화면의 함수(예: `getParam()`, `serializeObject('harContentsUpdateForm')`)를 불러 본문을 뜬다. **저장 버튼은 누르지 않는다.** 실제로 보내 봐야 할 때만 취소할 접수 건으로 보내고, `page.on("request")` 로 나간 본문을 기록한다.
5. 파이썬으로 같은 본문을 만들어 기록과 항목 순서·값을 대조한다.

도구: `tools/recon.py`(화면 수집), `tools/modify_truth.py`·`modify_screen_once.py`·`modify_spec_check.py`(수정 팝업). **이 도구들은 개발할 때만 쓴다. 프로그램은 브라우저를 쓰지 않는다**(09-30 확정 그대로).
IE 모드 전용이라고 알던 화면(납본자료접수의 수정 팝업, 원문등록 팝업)도 크롬 엔진에서 스크립트가 돌았다. 업로더 부품(DEXT5)만 IE 전용이고 그 부분은 이미 요청으로 대신하고 있다.

## 3. 시행착오 (같은 실수를 하지 말 것)
1. **썸네일을 원문일괄등록 요청에 원문유형 06 으로 보냄 → 거절.** "해당콘텐츠에 원문이 이미 존재합니다". 화면의 원문일괄등록 창 선택지가 열람·원본뿐인 데는 이유가 있었다. 접수 982 하나를 썼다.
2. **수정 팝업의 저장 본문(146칸)을 손으로 옮기려다 멈춤.** 서버 값 → 폼 → 본문의 대응이 450줄이었다. 2절의 방법으로 바꿔 화면의 스크립트에서 대응표를 뽑았다(`templates/modify_param_spec.json`).
3. **수정 화면의 저장은 그 자체로 자료를 바꾼다.** 생성일·작업일이 저장 시각으로, 입수일이 비고, 이용제한구분 `--`, MODS 에 빈 태그와 accessCondition 추가. 손으로 저장해도 같다. "저장 전후가 같다"는 확인을 그대로 걸었다가 전부 걸렸고, "값이 든 요소가 같다"로 바꿨다. **직원에게 알릴 사실.**
4. **지식 파일을 저장소에서만 고치면 다음 실행 때 사라진다.** `knowledge/*.md` 는 에이전트 작업 폴더(`%LOCALAPPDATA%\kolis_tool\agent\knowledge\`)가 원본이고 실행이 끝나면 저장소를 덮어쓴다. 손으로 고칠 때는 두 곳을 같이.
5. **"여러 작품이 접속 하나를 같이 써서 전송이 줄을 선다"고 유저에게 설명했으나 틀렸다.** 코드를 읽지 않고 클래스의 설명 글만 믿었다. 실제로는 실행마다 접속을 따로 만들고, 여러 작품을 못 돌린 이유는 `app.py` 가 썸네일 있는 작품에 걸던 옛 화면 잠금이었다. 세 작품을 동시에 걸어 보고서야 알았다. **설명하기 전에 그 경로의 코드를 읽는다.**
6. **유저의 질문 의도를 두 번 놓쳤다.** "여러 작품을 동시에 하면 느려지나, 병목을 줄일 방법이 있나"를 물었는데 측정 방법과 한도의 위치를 길게 답했다. 질문에는 먼저 예/아니오와 방법을 답한다.
7. **정리대상원부 목록 조회(`listAccRec.do`)가 4분 넘게 응답하지 않음(2번).** 서버에 무거운 조회다. 다시 보내지 않는다.
8. **같은 작품을 두 폴더로 돌리면 반입용 엑셀 파일 이름이 같아 덮어쓴다.** 시험하다 접수 985 로 반입했던 엑셀을 덮어썼다. 같은 제목의 탭 두 개는 KOLIS 등록을 동시에 걸 수 없다(작업 이름이 제목이라 "이미 진행 중").
9. **화면 코드(index.html)를 스크립트로 고치다 문자열 안에 줄바꿈이 들어가 탭이 전부 사라짐.** 창을 띄워 탭이 보이는지부터 확인한다. 화면 코드는 Edit 도구로 고친다.
10. **깃 배시에서 `/`로 시작하는 인자는 경로로 바뀐다** → `MSYS_NO_PATHCONV=1`. 임시 폴더에 `xml.py` 같은 이름의 파일을 두면 표준 모듈을 가린다. 긴 파이썬 조각은 heredoc 으로 넘기지 말고 파일로 써서 실행한다.
11. **sed 로 경로를 바꾸는 명령이 조용히 실패**해, "재실행"이 기존 작품 탭을 연 것뿐인데 끝났다는 알림을 받았다. 결과를 읽기 전에 무엇이 돌았는지(폴더, 걸린 시간)를 본다.
