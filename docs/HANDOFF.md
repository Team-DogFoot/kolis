## 0. 첫 세션이 곧바로 수행할 지시 (유저가 "시작"이라고만 하면 이 절을 그대로 실행한다)

상황: 도서관 작업용 PC(윈도, 내부망+외부망). 유저가 옆에 있고 직원도 있다. 원격 세션 없음. 9월 12일 맥북 세션에서 합의한 사항(2절)은 전부 유효하다.

1. `CLAUDE.md`, 이 문서 전체, `docs/FIELD-CHECKLIST.md` 를 순서대로 읽는다.
2. `docs/memory/*.md` 를 이 PC 의 클로드코드 메모리 폴더로 복사한다. 경로는 `%USERPROFILE%\.claude\projects\<이 저장소의 절대경로에서 구분자와 콜론을 -로 바꾼 이름>\memory\`. 이름은 실제 경로로 계산한다(예: `C:\Users\kkh\kolis` → `C--Users-kkh-kolis`). 이미 있으면 덮어쓴다.
3. 환경 확인(체크리스트 A): 파이썬·pip·`claude` 실행 가능 여부, `.venv` 존재 여부(없으면 `bin\setup.bat` 안내), `.env` 존재 여부(없으면 `.env.example` 복사 안내, 값은 유저가 직접 입력), 엣지 IE 모드 설정 위치, 외부 API 허용 여부, 보안 에이전트 종류. 결과를 체크리스트 A 에 바로 적는다.
4. **KOLIS 에 요청을 보내는 일은 직원 입회·동의 아래에서만.** 테스트 명목의 요청은 절대 보내지 않는다. 검증은 직원이 평소 업무를 할 때 남기는 HAR, 저장된 응답, `--preview` 로만.
5. 체크리스트 B 대로 HAR 기록 방법을 유저에게 단계별로 안내한다(엣지 F12 → 네트워크 → 로그 보존 → 작업 → HAR 내보내기). HAR 이 저장되면 이 PC 안에서만 읽어 로그인 폼 필드명과 화면별 요청을 확인하고 `kolis.json`(git 제외)과 체크리스트 B 에 반영한다. HAR 을 PC 밖으로 옮기지 않는다.
6. 콘텐츠 XML 1건을 `work/xml/` 에 저장하면 `python -m kolis_tool mods-check work/xml --wonbu <원부번호>` 로 점검기를 실제 응답에 맞춘다. 디지털콘텐츠관리의 "엑셀 반출" 버튼이 무엇을 주는지 확인한다.
7. 실제 접수분 1건으로 `bin\1_inspect.bat` 부터 5단계까지 순서대로. 각 단계가 끝나면 멈추고 결과를 보고한 뒤 유저 확인을 받고 다음으로 간다. 도구가 없는 단계(IE 모드 업로드, 전거·주제명 연결)는 유저가 손으로 하며, 그때 화면 캡처와 절차를 `docs/EXECUTION-LOG.md`(없으면 만든다)에 한 줄씩 기록한다.
8. 보고는 `CLAUDE.md` 의 보고 규칙대로. 세션 끝에는 체크리스트·EXECUTION-LOG·이 문서 3절(도구 상태)·`docs/memory/` 를 갱신하고 커밋·푸시한다.

국립중앙도서관 온라인자료과의 "웹툰 납본·수집 대행 사업". 출판사에서 받은 웹툰 이미지 파일을
도서관 통합자료관리시스템 KOLIS(엣지 브라우저, 일부 화면은 IE 모드)에 등록하고,
MODS 서지정보를 구축·점검해 납품한다. 목표 수량 50,000건(화). 반입 엑셀 1개당 500건.
절차 원문은 유저 PC의 `Downloads/웹툰 납본·수집 대행 사업_프로세스, 지침, 샘플파일/` 아래
`웹툰납본프로세스가이드v1.0.docx`(단계 ①~⑤), `웹툰대행사업 매뉴얼(v.1.6).pdf`, `참고자료(v.1.3).pdf`(계정 있음, 옮기지 말 것).

단계: ① 자료 수집(웹하드) → ② 검수(파일 오류·복본·유통가) → ③ KOLIS 등록(반입용 엑셀 → 일괄반입 → CNTS 폴더명 → 원문일괄등록 → 썸네일 → 등록대상처리 → 가원부) → ④ 구축(전거·주제명 연결) → ⑤ 점검(MODS 추출 → 규칙 점검 → 납품)

## 2. 유저와 합의한 방향 (2026-09-12 확정, 바꾸지 말 것)
1. **완전 자동화가 아니라 human-in-the-loop.** 사람이 판정하는 지점 4곳: 복본 판정, 반입 전 반입용 엑셀 확인, 저자전거·주제명 연결 승인, 점검 결과 확정.
2. **MODStoXL.exe 는 쓰지 않는다.** 그 프로그램은 KOLIS 에 로그인해 콘텐츠 XML 을 HTTP 로 받아 엑셀에 펼치는 것뿐이다(`kolis_tool/mods_fetch.py` 상단에 주소 기록). 정리 매크로(MODS_정리_V.2.0.xlsm)도 `mods_check.py` 로 대체했다.
3. **하이웨어(Hiware)+파일질라 SFTP 도 원칙적으로 쓰지 않는다.** 썸네일은 KOLIS 화면에서 건별 등록하는 것으로 간다. 단, 그 화면이 IE 모드 ActiveX 라면 1차는 사람이 하고 2차에서 UI 자동화 여부를 정한다.
4. **실행 환경: 윈도 네이티브 파이썬 + 클로드코드.**
5. **브라우저 자동화: 일반 화면은 Playwright 로 엣지 조작, IE 모드 ActiveX 화면(원문일괄등록·썸네일)은 1차에서 사람이 직접.**
6. **LLM 은 `agent --runner claude`(claude -p 헤드리스)가 기본.** `--runner codex`(codex exec), `--runner api`(claude-opus-5 직접 호출)도 가능. 13번 참조.
7. **산출물: 이 저장소 `kolis_tool` 파이썬 패키지, 명령줄 도구.** 사람 확인 지점은 엑셀 노란 셀. **1차는 명령줄, 완성 후 pywebview+FastAPI 로 창 하나짜리 UI**(일렉트론 안 씀).
8. **1차 목표: 실제 접수번호 1개를 ①~⑤ 전 과정 끝까지 통과.** 도구가 아직 없는 단계(IE 모드 업로드, 전거·주제명 연결)는 그 자리에서 사람이 손으로 하고, 그때 본 화면·HAR 로 다음 도구를 만든다. 단계를 뒤로 미루지 않는다.
9. **비밀번호는 환경변수(KOLIS_ID, KOLIS_PW, ANTHROPIC_API_KEY)로만.** 저장소·메모리·문서에 절대 적지 않는다. 참고자료 PDF 에 평문 계정이 있으니 그 파일을 복사·인용하지 않는다.
10. 유저 지시: LLM 보완 단계는 필요하면 웹 리서치(플랫폼 페이지 조회)를 포함한다.
11. **KOLIS 에 보내는 요청은 직원 입회·요청·동의 아래에서만.** 그 조건이면 브라우저 조작(Playwright)·computer use 등 효율적인 수단은 무엇이든 써도 된다.
    금지되는 것은 "테스트·검증한답시고" 직원 동의 없이 요청을 보내는 행위다. 콘텐츠ID 몇 건 시험 조회도 여기에 해당한다.
12. **코드 검증은 HAR(직원이 손으로 작업할 때 남긴 기록)·저장된 응답 파일·`--preview` 로만.** 첫 실제 실행은 실제 진행할 작품으로,
    직원과 함께, 진짜 제출하면서 한다. KOLIS 로 요청을 보내는 명령은 실행 전 확인(YES)을 거친다.
13. **LLM 보완은 `claude -p`(또는 `codex exec`) 헤드리스 실행이 1순위**(구독 요금, API 키 불필요). API 직접 호출은 대량 처리 때 대안. 질의는 작품당 1회 + 회차당 1회(타이틀컷 1장)로 묶는다.

## 4. 도서관 PC 에서 첫 세션이 할 일 (순서대로)
1. `docs/FIELD-CHECKLIST.md` A 항목(환경) 확인. 파이썬 설치 → `bin\setup.bat`(가상환경+설치). `.env.example` 을 `.env` 로 복사해 계정 입력.
   단계별 실행은 `bin\1_inspect.bat` … `bin\5_check.bat`(각 단계가 끝나면 멈추고 사람이 확인). 클로드코드 세션도 같은 단계 순서로 진행한다.
   Playwright 는 아직 설치하지 않는다(화면 확인 후).
2. 유저가 KOLIS 를 손으로 한 바퀴 돌리는 동안 HAR 을 남긴다(체크리스트 B). **HAR 은 이 PC 안에서만 읽는다.**
3. 콘텐츠 XML 1건을 `work/xml/` 에 저장하고 `python -m kolis_tool mods-check work/xml --wonbu <원부번호>` 로 점검기를 실제 XML 에 맞춘다(열 이름이 추출 예시와 같은지 확인).
4. HAR 에서 로그인 폼 필드명을 읽어 `kolis.example.json` 을 복사한 `kolis.json` 에 적는다(git 제외). **KOLIS 에 보내지 않는다.** `mods-fetch --preview` 로 보낼 요청을 출력해 HAR 의 요청과 글자 단위로 대조하는 것까지만.
5. 실제 접수분 1건: `inspect` → `rename --dry-run` → `convert` → 노란 셀 검토(`agent` 가능하면 실행) → 유저·직원이 반입.
   `mods-fetch` 의 첫 실행은 그 접수분의 점검 단계에서 직원과 함께 한다(결과 XML 이 화면의 XML 팝업과 같은지 직원이 확인).
6. 그날 확인된 사실을 `docs/FIELD-CHECKLIST.md` 에 채우고, 절차 변경은 `docs/EXECUTION-LOG.md`(새로 만들 것)에 한 줄씩.

## 5. 화면 캡처(가이드 그림 1~39)에서 확인한 사실 — 2026-09-12 맥북에서 이미지 전부 확인

- **크롬 엔진(일반 모드)인 화면**: 통합검색(`/cmmn/unisearch/uniSearchMain.do`), 등록원부작성 팝업(`/online/reg/bo/accrecmake/popup/onlineAccRec…`), 복본조사KEY설정(`/cmmn/dupexminkeyset/main.do`), 일괄복본조사, 디지털콘텐츠관리 및 일괄변경 팝업(`/online/cata/bocata/digitalcont/…`), MODS 입력 화면(표제·저자·출처·주제명, 전거 "찾기" 팝업). → Playwright 로 다룰 수 있는 범위.

- **전체출력 파일**은 `ExcelDown<숫자>.xls` 이름의 HTML 표(엑셀이 "형식 불일치" 경고). 열: No, 선정, 콘텐츠ID. `python -m kolis_tool ids <파일>` 로 ID 목록 추출.

- 점검 시트 배치(그림 36): 1행 오류표시·2행 COUNTA·3행 한글·4행 경로(필터)·5행부터 데이터, A~C 틀고정, 장르주제명 열은 분류기호 앞. `mods-check` 가 이 배치로 만든다.
- 등록원부작성 팝업 항목: 작성년도·등록구분(FTX)·콘텐츠수·파일수·가원부번호·원문서비스구분(07 납본뷰어) → "가원부번호부여".
- 일괄복본조사 KEY: 대상 온라인(단행), 1기준 낱권ISBN+매체구분+콘텐츠유형, 2기준 본표제/콘텐츠명 우절단 AND 저작자.
- 일괄변경 값: 자료유형1 CH1 e-콘텐츠, 자료유형2 CH11 기관수집(전자책·전자저널), 발행자구분 PE 일반, 공공누리유형 적용하지않음.
- 저자전거 "찾기" 팝업: 전거조회표목 입력 → 일치검색 → 전거유형·전거지역·채택표목·한자명·생몰년 표시 → 선택하면 @ID(KAC…)·@전거 자동 입력. 정확히 일치할 때만 연결(가이드 5.3).
- 매뉴얼 7.4: extent 는 "이미지 파일 16개 (12.5MB) : 천연색" 형식, 용량은 반올림 소수점 둘째 자리. 완료 사례는 내림·정수 표기라 서로 어긋남 → 현장에서 어느 쪽인지 확인(도구는 완료 사례 방식).
- 매뉴얼 9: 주기 입수처 예 "한국만화영상진흥원을 통해 수집한 자료임" — 수집 경로마다 다르다. 이번 접수분의 문구를 확인해 `convert_import.py` CONSTANTS 의 note#1 을 바꿀 것.
- 매뉴얼 14.1: 원문주소는 연재처 메인 URL + 작품 상세 URL 두 개 모두 기재. 연재처 소멸 시 기재하지 않음.
- 매뉴얼 2: 저자는 글·작가·그림·작화·각색·원작만. 어시스트·콘티·채색·배경·편집은 입력하지 않음(글·각색 없이 콘티만 있으면 콘티를 주저자로).

## 6. 알아둘 함정
- 출판사 zip 의 한글 파일명은 cp949 라 일반 도구로 풀면 깨진다. `python -m kolis_tool unzip <zip> -o <폴더>` 로 푼다.
- 출판사용 엑셀은 열이 23개 또는 24개("최초 연재 플랫폼" 추가)로 다르다. `convert` 는 헤더 이름으로 읽으므로 둘 다 된다.
- 반입용 양식은 예시(77열)와 완료 사례(88열: edition, 두 번째 publisher, 두 번째 url, 세 번째 note 추가)가 다르다. `convert --template` 에 실제 쓰는 양식을 주면 그 열 배치대로 쓴다.
- 완료 사례에서 확인된 표기: 권차 `01회`, 외전은 권차 대신 권차표제 `외전 01회`, 발행지 `[서울]`(플랫폼 출처라 각괄호)+`ulk`, 이용대상 주기 `15세 이용가`, 수집 주기 `한국웹툰산업협회를 통해 수집한 자료임`(acquisition), 정가 `무료` 회차도 500.
- 원문일괄등록: 5GB 에 1시간 반, 6GB 이상 오류 잦음, 오류 건은 시스템팀(주관기관)이 등록.
- 가이드가 "IE 모드에서만 동작"이라고 명시한 것은 원문일괄등록뿐. 다른 화면은 현장에서 확인.
