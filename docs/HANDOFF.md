## 1. 무엇을 하는 일인가
국립중앙도서관 온라인자료과의 "웹툰 납본·수집 대행 사업". 출판사에서 받은 웹툰 이미지 파일을 KOLIS(엣지, 일부 IE 모드)에 등록하고 MODS 서지정보를 구축·점검해 납품. 목표 50,000건(화). 반입 엑셀 1개당 500건.
절차 원문은 **`docs/source/`**(`docs/source/README.md` 참조). 단계: ① 수집 → ② 검수 → ③ KOLIS 등록(반입용 엑셀 → 일괄반입 → CNTS 폴더명 → 원문일괄등록 → 썸네일 → 등록대상처리 → 가원부) → ④ 구축(전거·주제명) → ⑤ 점검(MODS 추출·규칙 점검·납품).

## 2. 유저와 합의한 방향 (2026-09-12 확정, 바꾸지 말 것)
1. human-in-the-loop. 사람 판정 4곳: 복본 판정, 반입 전 반입용 엑셀 확인, 저자전거·주제명 연결 승인, 점검 결과 확정.
2. MODStoXL.exe·정리 매크로(`mods_check.py` 로 대체)·다크네이머(`rename_files.py` 로 대체)·하이웨어 SFTP 는 쓰지 않는다. 썸네일은 KOLIS 화면에서 건별 등록(자동화함).
3. 윈도 네이티브 파이썬 + 클로드코드. LLM 은 `claude -p` 헤드리스(리서치는 소넷 기본).
4. 계정은 `.env`·환경변수만. 참고자료 PDF 의 평문 계정을 옮기지 않는다.
5. KOLIS 요청은 직원 입회·요청·동의 아래에서만. 시험 요청 금지(콘텐츠ID 시험 조회 포함).
6. 유저가 정한 범위를 비용·시간 이유로 임의로 줄이지 않는다. 질문에는 답만, 행동은 지시가 있을 때.

## 2-2. 2026-09-29 유저 확정(추가)
- **주 목적은 프로그램 개발.** 작품을 통과시키는 것이 목적이 아니다. KOLIS 단계는 작품당 한 번뿐이라 시험 재료가 소모되므로 한 번에 1작품만 쓰고, 고친 뒤 다시 시험할 재료를 남긴다.
- **읽기·조사·판단은 에이전트(클로드코드 헤드리스)가 한다. 고정 코드는 형태가 정해진 것(83열 양식 쓰기, 형식·파일 증거 검사)에만.** 양식이나 사이트가 바뀌면 깨지는 코드(열 이름 고정, 플랫폼 고정 목록, 정규식으로 표기 정리, 결론 규칙)를 만들지 않는다.
- **에이전트를 함수처럼 한 번 부르고 끊지 않는다.** 에이전트가 스스로 돈다: 일 → 결과 저장 → 검사 도구를 직접 실행 → 걸린 것을 고침 → 검수 에이전트 → 배운 것 기록. 프로그램이 이어서 시켜야 하면 새로 시작하지 않고 같은 대화를 잇는다(`--resume`). 지식은 스킬과 `knowledge/` 에 쌓는다.
- **납품 폴더 → 반입용 엑셀은 버튼 하나.** 화면은 폴더, 작업 번호, 파일명, 지시·메모, 실행. 중간 엑셀(표준 엑셀)과 반입용 엑셀의 `_source` 시트는 없앴다. 다시 만들지 않는다.
- **시험은 프로그램 창으로**(0절 5번). 같은 작품을 두 번 돌려 반입용 엑셀의 값이 같은지 확인한다.
- 모델은 Sonnet. 금액은 보고하지 않는다(구독이라 청구되지 않음. 걸리는 것은 사용량 한도).
- 썸네일이 동봉되지 않은 납품은 썸네일을 등록하지 않는다(직원 확인). 반입용 엑셀의 thum_files 도 비운다(채우면 0 Bytes 자리표시자 행이 생김).
- 발행일 규칙(가장 이른 공개일)은 권 단위 자료에도 적용.
- 사람에게 보여 주는 칸 이름은 반입용 엑셀의 열 이름(MODS) 기준, 한글은 괄호 안.
- 여러 작품을 탭으로 동시에. 1단계는 동시 실행, KOLIS 단계는 화면 조작인 동안 한 번에 한 작품. 요청 방식으로 바뀐 단계부터 잠금을 푼다.
