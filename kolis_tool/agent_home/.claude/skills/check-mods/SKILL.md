# MODS 점검(판단 항목) — 프로세스 가이드 5.8

입력 `jobs/<작업>/job.json`: `wonbu`, `nth`(n차), `columns`(시트 열 = MODS 경로. 같은 경로의 두 번째 등장은 `[1] /mods/…`), `rows[]`(콘텐츠마다 `{contents_id, vol, values{열: 값}}`), `labels`(열의 한글 이름), `observations_dir`(1단계 관찰 파일 폴더, 없으면 null), `authority_cache_dir`(전거 조회 기록 `<이름>.json`), `import_available`.
형식 규칙(발행일 8자리, ISBN 검증 숫자, 부호표, 고정값 등)은 프로그램이 이미 검사했다. 당신은 **판단이 필요한 항목**만 본다.

## 0. 기준(먼저 읽는다)
`knowledge/rules/build-judgment-rules.md`(직원 답변, 최우선), `knowledge/rules/MODS_입력가이드.md` 2·2.1~2.4·5·5.2·8·9·10, `knowledge/corrections.md`.

## 1. 보는 것(가이드 5.8 의 "각 항목 클릭하여 맞게 들어갔는지 확인")
1. **저자명과 유형(개인명/단체명) 일치**: 스튜디오·팀·출판사 이름인데 personal, 사람 이름인데 corporate. 근거는 관찰 파일(크레딧면 글자)·전거 기록. 확신이 없으면 `check`.
2. **전거 연결 적정**: `/mods/name[@ID]` 가 있는 저자는 `authority_cache_dir/<이름>.json` 의 그 후보(JOB·BIRTH_YEAR·SUMMARY)가 이 작품 저자와 맞는지. 이름만 같은 다른 직업이면 `error`(기준: 직원 답변 1~3). 전거가 없는 저자 중 후보 기록에 만화가가 있는데 연결하지 않았으면 `check`.
3. **다른이름**: 값이 있으면 관찰 파일에 그 글자가 있어야 한다(직원 답변 7·10). 없으면 `error`. 영문이 '성, 이름' 꼴이 아니면 `check`(답변 8). 유형값이 뜻에 맞는지(nickname = 필명, formal name = 본명).
4. **디스플레이형식**: 전거 연결 저자에만, 원문 표기와 같은지(가이드 2.2).
5. **발행처·발행지**: 발행처가 둘 이상이면 발행처가 먼저이고 제작처는 `○○ [제작]`(한 칸 띄움)인지, 발행지가 다른 제작처는 둘째 출처정보에 있는지(가이드 5·5.2), 둘째 출처정보에 발행일이 없는지(답변 17), 발행처 각괄호 없음.
6. **주기**: 임프린트·필명 주기가 원문 근거가 있는지, 이용대상 주기 문구가 이용대상자 값과 맞는지(성인용 ↔ "19세 미만 구독불가", 15세 ↔ "15세 이용가"), 입수처 주기 문장.
7. **대등표제**: `[1] /mods/titleInfo/title` 이 있으면 `[1] /mods/titleInfo[@type]` 가 parallel 인지.
8. **회차끼리**: 같은 작품인데 저자·발행처·주제명·주기가 회차마다 다르면 다수와 다른 회차에 `check`(어느 쪽이 맞는지 근거와 함께).

## 2. 결과 파일 `jobs/<작업>/findings.json`
```json
{"wonbu": "", "nth": 1,
 "findings": [{"row": 0, "col": "/mods/name[@type]", "level": "error|check", "msg": "직원이 읽을 한 문장(값을 넣어)", "basis": "지침 2 | 직원 답변 1 | 관찰 CNTS-…/00000002.jpg", "evidence": [{"file": "", "quote": ""}]}],
 "notes_for_staff": ["작품 전체에 해당하는 참고"],
 "review": {"done": false, "findings": [], "resolved": []}}
```
- `row` 는 `rows` 의 순서(0부터), `col` 은 `columns` 의 열 이름 그대로.
- `error` 는 지침·직원 답변 번호 또는 원문 파일이 `basis` 에 있어야 한다. 확신이 없으면 `check`(파란 칸 — 직원이 보고 틀린 게 없으면 채우기 없음으로).
- 글투: 합니다체 완결문, 값을 넣어 쓴다. 영어 낱말·필드 경로·"에이전트"는 쓰지 않는다.

## 3. 검사·검수
`{PY} -m kolis_tool check-findings "<findings.json 절대 경로>"` 로 형식을 확인하고, `reviewer` 에이전트에게 검수를 받아 `review.done` 을 true 로 한다. 지어내지 않는다. 확인하지 못한 것은 `check` 로 두고 그 사실을 적는다.

## 4. 끝
마지막 답 한 줄: 오류 수 · 확인 수 · 직원에게 알릴 것.
