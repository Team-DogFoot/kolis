# 납품 폴더 → 반입용 엑셀

입력 `jobs/<작업>/job.json`:
- `folder` 납품 폴더(읽기 가능), `snapshot` 폴더 구성과 엑셀의 모든 칸을 글로 옮긴 파일, `output_xlsx` 반입용 엑셀이 쓰일 경로
- `instructions` **직원이 이 작품에 대해 적은 지시·메모. 다른 모든 기준보다 우선한다.**
- `batch_note` 비고에 들어갈 작업 번호(있으면)

만드는 파일(모두 `jobs/<작업>/` 안): `research.json`(조사 결과), `import.json`(반입용 엑셀에 들어갈 값). 반입용 엑셀 자체는 명령이 쓴다.

## 0. 시작하기 전에
`knowledge/platform-notes.md`, `knowledge/corrections.md` 를 읽는다. 직원이 전에 고친 내용과 같은 상황이면 그 판단을 따른다.
기준이 헷갈리면 `knowledge/rules/INDEX.md` 로 찾아 `MODS_입력가이드.md`(태그별 입력 가이드), `웹툰대행사업_매뉴얼_v1.6.md` 에서 항목 이름으로 찾아 읽는다.

## 1. 납품 자료 읽기
1. `snapshot` 파일을 읽는다. 출판사마다 엑셀 양식(열 이름·열 수·머리글 위치)과 폴더 구성이 다르다. 열 이름이 달라도 뜻으로 판단한다.
2. 원고 폴더를 찾는다: 회차(또는 권)마다 폴더가 하나씩 있다. 엑셀의 자료 행과 짝짓는다. 폴더 모양이 정리 뒤의 모양(1-5)과 다르면 정리 계획을 세운다.
3. 원고 이미지를 Read 로 직접 본다: 첫 폴더의 처음 2~3장, 마지막 폴더의 마지막 2~3장(판권면이 있는 경우가 많다), 폴더마다 첫 장.
   볼 것: 표지·타이틀컷의 제목 표기(띄어쓰기 포함), 권차 표기 방식, 저자 표기와 역할, 색(**내용(본문)** 기준 — 표지만 천연색이고 내용이 흑백이면 흑백. 폴더 단위로 판단), 판권면의 출판사·발행일·ISBN.
4. 썸네일 폴더가 있으면 자료 행과 썸네일 파일을 짝짓는다. 없으면 썸네일은 등록하지 않는다(직원 확인 2026-09-29).

## 1-5. 납품 폴더 정리 계획 (`arrange`)
출판사가 보낸 폴더는 모양이 제각각이다(회차 폴더와 썸네일 폴더가 한곳에 섞여 있음, 폴더 이름에 `★`·`#` 같은 표시, 한 겹 더 싸인 폴더, 원고 폴더 안의 이미지가 아닌 파일 등). KOLIS 에 올리려면 아래 모양이어야 한다. **당신이 분류하고 정리 계획을 정한다. 실제로 옮기는 일은 프로그램이 끝에 한다**(당신은 납품 폴더를 고칠 수 없다). 검사와 반입용 엑셀 쓰기는 계획을 적용한 뒤의 모습을 기준으로 돈다.

정리 뒤의 모양:
- **원고 상위 폴더**(`manuscripts_root`) 하나. 그 바로 아래에는 **회차(권) 폴더만**, 자료 행 수와 같은 개수로. 파일이나 다른 폴더(썸네일 등)가 있으면 안 된다.
- 회차 폴더 안에는 **이미지만**. 이미지가 아닌 것(Thumbs.db, txt, psd, 하위 폴더 등)은 `set_aside` 로 `_kolis_제외/…` 에 빼 둔다. **지우는 계획은 없다.**
- 썸네일이 있으면 **썸네일 폴더**(`thumbs_dir`) 하나에 썸네일 파일만.
- 이미 이 모양이면 옮기지 않는다(`moves`, `set_aside` 를 비운다). 한 번 정리된 폴더를 다시 맡았을 때도 마찬가지다.

정하는 법:
- 폴더·파일이 무엇인지(회차 원고, 썸네일, 표지, 홍보물, 엑셀, 그 밖)를 이름과 내용으로 분류한다. 헷갈리면 이미지를 직접 열어 본다.
- 회차 폴더와 엑셀의 자료 행을 **뜻으로** 짝짓는다. 본편과 외전·예고편·프롤로그는 번호가 겹쳐도 다른 회차다. 숫자만 보고 짝짓지 않는다.
- 회차 폴더의 새 이름은 자료 행 순서가 드러나게 짓는다: `<세 자리 순번>_<권차 표기>`(예 `001_예고편`, `002_1화`, `007_외전 1화`). `★`·`#` 같은 표시는 뺀다. (이 이름은 KOLIS 등록 때 콘텐츠ID 로 다시 바뀐다.)
- 폴더는 통째로 옮긴다. 폴더와 그 안의 파일을 따로 `moves` 에 넣지 않는다(그 안에서 빼 둘 파일은 `set_aside` 에, **지금 경로**로 적는다).
- 짝이 안 맞는 것(엑셀에 없는 폴더, 폴더가 없는 행, 빈 폴더, 중복으로 보이는 폴더)은 억지로 맞추지 않는다. 옮기지 않고 `arrange.notes` 와 `issues` 에 적는다.
- `rows[].folder`, `thumb_source`, `manuscripts_root`, `thumbs_dir` 는 **정리 뒤의 이름**으로 적는다.

## 2. 조사
`research-work` 스킬의 "2. 무엇을 정하는가", "3. 결과 파일", "4. 스스로 검사"를 그대로 따른다(`.claude/skills/research-work/SKILL.md` 를 읽는다).
결과는 `jobs/<작업>/research.json`, 검사는 `{PY} -m kolis_tool check-research "jobs/<작업>/research.json"`.
이 단계의 검수(research-work 5번)는 건너뛴다. 검수는 맨 끝에 한 번 받는다. 검사가 "검수를 아직 받지 않았습니다"만 남으면 다음으로 간다.

## 3. 칸마다 값 정하기
정보원 우선순위(매뉴얼): **원고(으뜸정보원) > 출판사 엑셀(으뜸정보원) > 플랫폼 화면(참고)**.
플랫폼 화면에서만 확인한 값은 **각괄호로 묶는다**(예: 발행지 `[서울]`). **단, 발행처(`publisher`)에는 어떤 경우에도 각괄호를 넣지 않는다**(직원 규칙 2026-10-01). 원고·출판사 엑셀의 값에 각괄호가 들어 있으면 원괄호로 바꾼다.
출판사가 적은 값과 확인한 사실이 다르면 기준에 따라 고르고, 그 칸을 `confirm` 에 넣어 사람이 확인하게 한다. 관행으로 정한 값, 확신이 낮은 값도 `confirm` 에 넣는다.
`confirm` 은 행마다 따로다. 같은 확인이 여러 행에 해당하면(제목, 발행처, 발행일 등) **해당하는 모든 행에 같은 문구로** 넣는다. 그래야 반입용 엑셀에서 그 칸들이 전부 노란색으로 표시된다.

**`confirm` 은 직원이 읽는 글이다.** 직원은 여러 작품을 동시에 맡고, 당신이 무엇을 조사했는지 모르고, 이 작품을 처음 본다. 한 항목만 따로 읽어도 무슨 일인지 알고 바로 정할 수 있게 쓴다.
- `reason` 왜 확인이 필요한지. 한두 문장. 무엇과 무엇이 다른지, 또는 무엇을 확인하지 못했는지를 **값을 넣어** 적는다("다릅니다"만 쓰지 않는다).
- `publisher_says` 출판사 엑셀에 적혀 있던 값 그대로(칸 주소와 함께, 예: `E5 '20240410'`). 출판사 엑셀에 그 칸이 없으면 `없음`.
- `evidence` 넣은 값의 근거. 어디서 무엇을 봤는지: 플랫폼 이름 + 주소 + 화면에 적힌 글자, 또는 원고 파일 이름과 본 내용. 직원이 눌러서 바로 볼 수 있게 주소를 그대로 적는다.
- `ask` **직원이 정할 것**을 질문으로. 고를 수 있는 값을 함께 적는다. 예: "발행일을 플랫폼 공개일(20240409)로 둘까요, 출판사 엑셀 값(20240410)으로 바꿀까요?"
- 쓰지 않는 말: `confirm`, `research.json`, `values`, 항목의 영어 이름(직원에게 보이는 칸 이름은 프로그램이 붙인다), "직원 규칙", "관행". 대신 무슨 기준인지 풀어서 쓴다(예: "무료로 공개된 회차는 정가 0·보상 N 으로 넣는 기준에 따랐습니다").
- 한 줄에 여러 사실을 몰아넣지 않는다. 약어·줄임말을 쓰지 않는다.

| 항목 이름 | 넣는 값과 기준 |
|---|---|
| `title` | 본표제. 원고 표기 그대로(띄어쓰기 포함). 표제 앞 관제는 원괄호로. 제목 뒤 숫자·로마자는 본표제에 포함 |
| `title_parallel` | 대등표제. 원고·플랫폼에 외국어 제목이 본표제와 함께 적혀 있을 때만(예: `Delight`, `Battle Slime`). 프로그램이 유형 `parallel` 을 같이 넣는다. 없으면 비움 |
| `subTitle` | '시즌 2', '외전' 등 시리즈·시즌·외전 문구, 총서 이름(예: `강촌 창작극화`). 원문 그대로 |
| `partNumber` | 권차. **원고 표기 그대로**('1화', '01회', '1권', '최종화'…). 원고에 단위 없이 숫자만 있으면 출판사 엑셀 표기를 따른다. 프롤로그·에필로그·예고편은 권차를 비우고 `partName` 에. **본편의 마지막 회차에는 권차 뒤에 ` (완결)` 을 붙인다**(5차 완료 사례 9건 중 8건의 표기: `50화 (완결)`, `16 (완결)`. 외전이 뒤에 있어도 본편 마지막 회차에 붙인다). 연재 중이거나 완결인지 확인하지 못했으면 붙이지 않고 확인할 칸에 넣는다 |
| `partName` | 회차 제목(화수 뒤에 오는 제목) |
| `names` | 저자 `[{"name","type":"개인명|단체명","role"}]`, **수 제한 없음**(양식 열은 프로그램이 저자 수만큼 늘린다). 정보원에 쓰인 순서대로. 이름은 **전거형**(아래 3-1 의 가이드 2.1 — `authority` 명령으로 확인). 역할어는 명사형(글, 그림, 원작, 각색, 글·그림). 플랫폼 화면에서만 확인한 저자는 각괄호로 묶고 `from.names` 에 `플랫폼` 을 적는다 |
| `publisher` | 발행처(첫째). 원문에 발행처가 있으면 그것, 없으면 최초 발간 플랫폼. 각괄호 없이 이름만. 영문은 각 단어 첫 글자만 대문자(가이드 5.2, 머리글자 약어만 예외) |
| `publishers` | 둘째 이후 발행처·제작처·유통사 목록 `["미스터블루"]`(가이드 5: 발행처 › 제작처 › 유통사 순, 발행지가 같을 때). 둘 이상이면 관계를 `other_note` 에 적는다(예: `Studio Bluelime은 미스터블루의 임프린트임`). 없으면 비움 |
| `edition` | 판사항. 원문·플랫폼에 개정판, 19세 완전판, 제2판 같은 판 표시가 있을 때만 그대로(숫자는 아라비아, '판'자가 없으면 `개정[판]`)(가이드 5.4). 없으면 비움 |
| `origin2` | 둘째 출처정보 `{"type":"","issuance":"단행자료","publisher":"○○[제작]","dateIssued":""}`. **발행지가 다른 제작처**가 있을 때만(가이드 5.2). 보통 비움 |
| `notes_extra` | 넷째 이후 주기 `[{"text":"문화체육관광부장관상, 2025","type":"awards"}]`(가이드 9: 수상 등). 없으면 비움 |
| `place`, `place_code` | 발행지와 발행국 부호. 예: `[서울]` + `ulk`, `[안양]` + `ggk`(경기). 부호는 `knowledge/rules` 의 지침서 발행국 부호를 따른다 |
| `dateIssued` | 그 권·회차의 공개일 YYYYMMDD(research.json 의 episodes). 못 찾았으면 비우고 confirm |
| `color` | `천연색` 또는 `흑백`(매뉴얼 7.4). 그 폴더의 **내용(본문)** 기준. 표지=천연색, 내용=흑백이면 `흑백` |
| `targetAudience`, `audience_note` | 여러 플랫폼의 등급 중 나이가 가장 많은 것(15세와 19세면 19세). 기본 `일반이용자` + 주기 `전체이용가`. 15세면 `일반이용자` + `15세 이용가`. 성인이면 `성인용` + `19세 미만 구독불가` + `licenseType` 을 `1` 로 |
| `licenseType` | 접근제한유형. 기본 `2`, 성인용은 `1`(완료 사례) |
| `acquisition_note` | 입수처 주기. 5차 완료 사례는 모두 `한국웹툰산업협회를 통해 수집한 자료임`. 수집 경로가 다르다는 지시가 있으면 그에 따른다 |
| `other_note` | 일반 주기(유형 없음). 가이드 9 순서로 첫째 자리: 약어 풀이, 저자 본명·필명 관계(그 이름은 다른이름으로도), 발행처·임프린트 관계(`A은 B의 임프린트임`). 없으면 비움 |
| `identifier`, `identifier_type` | ISBN(**숫자만, 붙임표 `-` 없이** 13자리) + `isbn`. **권·회차마다 개별 ISBN**(research.json). 어디에서도 못 찾고 세트 ISBN 만 있을 때만 마지막 수단으로 세트 ISBN(confirm). ISBN 이 여럿이면 출간일이 가장 이른 것. 출판사 엑셀의 값이 확인한 값과 다르면 확인한 값을 쓰고 confirm. UCI 는 반입 시 등록할 수 없으므로 비우고 confirm 에 "구축 단계에서 직접 입력"이라고 적는다 |
| `url_main`, `url_work` | 원문주소. `url_main`(첫 번째 /mods/location/url) = 그 작품이 들어 있는 목록 페이지(만화·웹툰 등. 예 `https://www.mrblue.com/comic`). `url_work`(두 번째) = 그 작품의 회차들이 보이는 페이지(예 `https://www.mrblue.com/comic/C000075511`). 지금 열려야 한다 |

## 5. 반입용 엑셀 쓰기와 검사
`{PY} -m kolis_tool write-import "jobs/<작업>/import.json"`

이 명령이 값을 파일 증거·형식과 대조하고, 형식이 맞으면 반입용 엑셀을 쓴다. 걸린 항목을 읽고 `import.json` 을 고친 뒤 다시 돌린다.
검사를 통과시키려고 값을 지어내지 않는다. 정할 수 없는 값은 비우고 confirm 에 이유를 적으면 된다.

## 6. 검수받기
"검수를 아직 받지 않았습니다"만 남으면 `reviewer` 에이전트에게 맡긴다(Agent 도구). 넘길 말: `job.json`, `research.json`, `import.json` 경로.
지적을 하나씩 처리한다: 맞으면 고치고, 아니면 왜 아닌지 근거를 댄다. 처리 내용을 `import.json` 과 `research.json` 의 `review.findings` / `review.resolved` 에 적고 `review.done` 을 true 로 한다.
그다음 4번(조사 검사)과 5번(쓰기와 검사) 명령을 다시 돌려 둘 다 "통과"를 확인한다.

## 7. 배운 것 적기
새로 알게 된 요령을 `knowledge/platform-notes.md` 에 덧붙인다(research-work 6번과 같다). 출판사 엑셀 양식에 대해 알게 된 것(이 출판사는 열 이름을 이렇게 쓴다 등)도 적는다.
