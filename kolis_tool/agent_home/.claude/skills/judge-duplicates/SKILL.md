# 복본조사 결과 판정 (구축 5.1)

입력 `jobs/<작업>/job.json` (프로그램이 KOLIS 화면·조회로 모은 것. 당신은 KOLIS 에 접근하지 않는다):
- `wonbu`, `title`
- `ours[]` : 우리 자료(정리 대상) 종마다 `{row_key, ident, table_row, detail, volumes}`. `detail` 은 종 상세(TITLE, SUBTITLE, VOL, AUTHOR, PUBLISHER, PROD_DAY, EA_ISBN, SET_ISBN, ISSUANCE, ACQUISIT_YR, ACQUISIT_CODE, WORKING_STATUS, SPECIES_GBN, REG_CODE, OFFER_DBCODE_1S, USE_OBJ_CODE, NOTE, CONTROL_NO …), `volumes` 는 권 목록(VOL, TITLE, PROD_DAY, CNTS_CNT, ACQ_STATUS, REG_DT …).
- `candidates[]` : KOLIS 가 찾아 준 후보 종마다 `{rec_key, detail, volumes}`(같은 꼴).
- `pairs[]` : 우리 종 ↔ 후보 종 짝(`our_key`, `cand_key`, `table_row`). **판정은 이 짝마다** 한다.

**전제(사실):** `candidates[]` 는 KOLIS 가 표제·저작자로 찾은 **등록 자료 전부**다. 같은 발행처·같은 발행일의 후보 종 수가 곧 KOLIS 에 등록된 그 자료의 권 수다(예: 저스툰 후보 8종 = 저스툰 등록본은 1~8권뿐). 다른 플랫폼 화면(무툰 등)의 회차 수는 KOLIS 등록본의 권 수가 아니다. 검수 때도 이 전제로 본다.

출력 `jobs/<작업>/dup_build.json` (아래 "결과 파일").

## 0. 시작하기 전에 — 기준 원문을 읽는다
1. `knowledge/rules/정리지침서_2025.md` 의 "쪽 10"(일괄복본조사): 상세보기에서 **"이미 동일한 자료(자료유형 및 파일형식까지 동일한 경우)"** 가 있으면 구축제외목록으로 표시하고 **국중 담당자 문의 후 최종 판단**.
2. `knowledge/rules/웹툰대행사업_매뉴얼_v1.6.md` 의 "쪽 4~5"(자료 검수 — 복본 조사, 완결 여부): 표제·저작자·발행자로 검색해 상세·원문 대조 / **파일 형식만 다르고 내용이 같으면 한 형태만 납본 가능** / 1부 완결 뒤 2부가 101화부터 이어지면 미완결, 1화부터 다시 시작하면 1부는 완결.
3. `knowledge/rules/웹툰납본프로세스가이드_v1.0.txt` 의 "② 납본 자료 검수 — 복본조사 절차": **판사항(일반판·완전판·개정판)이 다르면 수집 가능 / 수집상태가 "보존"이면 추가 수집 가능 / 일부 회차만 등록돼 있으면 등록되지 않은 회차는 수집 가능**.
4. `knowledge/rules/build-judgment-rules.md` 26(복본 판정 위임)과 `knowledge/corrections.md`.

## 1. 도구
- WebSearch, WebFetch, `{PY} -m kolis_tool render "<주소>"`. 같은 작품인지 가릴 때 플랫폼 작품 화면(권 수·회차 수·출판사·연재 시기)과 국립중앙도서관 서지정보(`https://www.nl.go.kr/seoji/…`)를 본다. 명령 뒤에 다른 명령을 잇지 않는다.

## 2. 어떻게 판정하는가 (짝마다)
1. **같은 작품인가**: 표제(부제 포함)·저작자가 같고, 권차/회차가 대응하는가. 표제가 같아도 저작자가 다르면 다른 작품.
2. **같은 내용인가**: 같은 작품이라도 ① 판사항이 다르면(개정판·완전판·채색판 등) 복본 아님 ② 우리 권차가 후보에 없으면(일부 회차만 등록) 그 권차는 복본 아님 ③ 후보가 **플랫폼 수집본**(발행처가 플랫폼, ISBN 없음, 수집 D1)이고 우리 것이 **출판사 납본 단행본**(ISBN 있음)이면, 내용이 같은지 웹에서 확인한다. 같은 내용이면 매뉴얼의 "파일 형식만 다른 같은 내용 → 한 형태만 납본"에 해당하므로 **복본** 쪽으로 보되, 확신이 없으면 **판단 불가**.
3. **발행처·발행년이 달라도** 내용이 같을 수 있다(재유통·단행본화). 발행처 차이만으로 "복본 아님"으로 단정하지 않는다.
   - 권차가 다른 짝: 등록 자료 묶음(같은 발행처·같은 발행일의 종들)의 권 수가 우리 권 수와 같고 권차 번호가 1:1 로 대응하면(예: 우리 1~8권 ↔ 등록 1~8권), 권차가 다른 짝은 **복본 아님(high)** 으로 보고, 같은 권차 짝만 내용 동일 여부를 따진다. 권 수가 다르거나 번호 체계가 다르면(플랫폼이 연재 회차를 "N권"으로 부르는 경우) 그때만 판단 불가로 둔다. 판정은 실행마다 같아야 하니 이 기준을 먼저 적용하고 이유에 적는다.
4. 결정: `dup`(복본 — 같은 작품·같은 내용·같은 권차, 근거 있음) / `not`(복본 아님 — 다른 작품, 다른 판, 미등록 권차 등 **확실한** 근거 있음) / `unsure`(가릴 수 없음 — 무엇을 보면 가릴 수 있는지 `to_check` 에). 확신 `confidence` 는 high/medium/low. **`dup` 과 `not` 은 high 일 때만. 같은 작품·같은 권차인데 내용이 같은지 가리지 못했으면 반드시 `unsure`.** `not` 이면서 직원에게 확인을 부탁하는 글을 쓰지 않습니다. 발행처·발행년 차이는 복본 아님의 근거가 아닙니다(3번).
5. 지침대로 `dup` 이 하나라도 있으면 프로그램은 완료 처리를 멈추고 국중 담당자 문의로 넘긴다. 당신은 `summary` 에 담당자가 바로 읽을 한 문단(어느 종이 어느 등록 자료와 같은지, 왜)을 쓴다.

## 3. 결과 파일 `dup_build.json`
```json
{
 "wonbu": "", "title": "",
 "pairs": [{"our_key": "", "cand_key": "", "verdict": "dup|not|unsure", "confidence": "high|medium|low",
            "same_work": true, "reason": "", "evidence": [{"url": "", "quote": ""}], "to_check": ""}],
 "summary": "담당자가 읽을 한 문단",
 "counts": {"dup": 0, "not": 0, "unsure": 0},
 "review": {"done": false, "findings": [], "resolved": []}
}
```
`pairs` 는 job 의 짝 **전부**에 대해 하나씩. 같은 후보 종이 여러 우리 종과 짝지어졌으면 짝마다 따로 적되 이유는 짧게 반복해도 된다. 웹에서 본 것은 **찾지 못했어도** `evidence` 에 주소와 화면 글자 그대로 남깁니다(`dup`·`unsure` 는 근거가 하나도 없으면 검사에 걸립니다).

### 글투 — 처음 읽는 직원 기준
합니다체 완결문. 영어 낱말·칸 이름(REC_KEY 같은 것)·내부 말("짝", "종", "키")은 쓰지 않는다. "우리 자료 ○권"과 "등록 자료 ○권(발행처, 발행일)"으로 부른다.
`summary` 는 배경을 모르는 사람이 읽는다. 순서: ① 무엇을 비교었는지 한 문장(예: "우리 자료 등짝 1~8권을 KOLIS 가 찾아 준 등록 자료, 저스툰 수집본 1~8권과 권마다 비교었습니다") ② 결과를 우리 자료 기준으로(예: "같은 권차끼리는 내용이 같은지 가리지 못했고, 다른 권차끼리는 다른 권이라 복본이 아닙니다") ③ 담당자가 할 일 한 문장. 숫자는 "8권 모두"처럼 사람이 세는 단위로.
`reason` 도 그 줄만 읽고 알 수 있게: 무엇이 같고 무엇이 달랐는지 → 그래서 어떤 판정인지.

## 4. 스스로 검사
`{PY} -m kolis_tool check-dup "jobs/<작업>/dup_build.json"` — 통과할 때까지 고친다.

## 5. 검수받기
`reviewer` 에이전트에게 `dup_build.json`·`job.json` 경로와 "복본 판정 검수"를 넘긴다. 지적을 반영하고 `review.done` 을 true 로 한 뒤 4번을 다시 돌린다.

## 6. 배운 것
플랫폼 수집본과 단행본의 대응을 가릴 때 쓸 만한 요령만 `knowledge/platform-notes.md` 에.

## 7. 끝
마지막 답: 결과 파일 경로, 복본/아님/불가 수, 담당자 문의가 필요한지 한 줄.
